# Spendly — учёт семейных расходов

Член семьи пишет боту в Telegram «кофе 350», и трата сохраняется: сумму, категорию и дату бот определяет сам. Глава семьи видит траты всех в веб-панели.

## Быстрый старт

```bash
make up
```

Это `cp .env.example .env && docker compose up --build`. Поднимутся Postgres, разовые миграции и приложение.

- Панель: http://localhost:8080 — сразу с демо-семьёй (`SEED_DEMO=true`).
- Документация API: http://localhost:8080/docs (OpenAPI: `/api/openapi.yaml`).

Чтобы заработал бот, в `.env` нужны два значения:

- `TELEGRAM_TOKEN` — токен от [@BotFather](https://t.me/BotFather);
- `LLM_API_KEY` — ключ провайдера LLM. По умолчанию Claude (`claude-opus-5-5`); OpenAI, OpenRouter и Ollama — примеры в `.env.example`.

Без токена приложение запускается без бота, панель работает.

## Как проверить за 5 минут

1. `make up` и открыть панель: фильтры по участнику, периоду и категории, добавление, изменение, удаление.
2. Указать токен и ключ в `.env`, `make up`, написать боту:
   - `кофе 350`, `такси 1200 вчера`
   - `сколько потратил на еду в этом месяце`, `покажи траты за неделю`
   - `последнее было не 350, а 450`
   - `удали такси`
3. Траты из бота появятся в панели. Второй аккаунт Telegram увидит в боте только свои траты.
4. `make test` — тесты в контейнере, локальный Go не нужен.

## Архитектура

Один Go-бинарник, Postgres. Подкоманды: `serve` (API, панель, бот) и `migrate`.

```
Telegram ──long polling──► bot ──► agent ──► LLM (OpenAI-совместимый API)
                                     │ tools
                                     ▼
                         db.ForUser(user)      — только траты автора сообщения
                                     │
Браузер ──► api (REST) ──► db.ForFamily(family) — траты всей семьи
                                     │
                                  Postgres
```

| Пакет | Что делает |
|---|---|
| `internal/expense` | модель, деньги, категории, валидация, SQL; хранилище, ограниченное семьёй или пользователем |
| `internal/agent` | цикл tool calling, 5 инструментов, системный промт, LLM-клиент |
| `internal/bot` | приём сообщений: личка, `/start`, доступ, защита от повторов, лимиты, история |
| `internal/api` | REST API, OpenAPI, раздача панели |
| `web/index.html` | панель на чистом JS |
| `migrations/` | схема (goose) |

### Ключевые решения

- **Изоляция пользователей обеспечивается кодом, а не промтом.** Агент получает только хранилище `db.ForUser(...)`, созданное из `message.From.ID`. Ни один инструмент не принимает `user_id`, а владелец проверяется в каждом SQL-запросе (`WHERE ... AND user_id = $n`). Чужой id от модели даёт «не найдено» — это проверяют тесты.
- **Tool calling вместо «фраза → JSON».** Для «удали такси» и «последнее было не 350» модели нужно видеть траты пользователя: сначала `find_expenses`, потом `update_expense` / `delete_expense` по id. Если подходит несколько трат, бот спрашивает, а не угадывает.
- **Суммы считает SQL** (`sum_expenses`), модель только формулирует ответ.
- **Деньги — копейки в `int64`**, в БД `NUMERIC(12,2)`. `spent_at` — `DATE`, «сегодня» считается в `APP_TIMEZONE`.
- **Ответ модели проверяется так же, как запрос из API:** категория из списка (плюс `CHECK` в БД), сумма больше нуля, дата не в будущем. Ошибка возвращается модели, и она переспрашивает пользователя.
- **Без лишних слоёв.** Нет service/repository-интерфейсов с одной реализацией; интерфейс один — LLM (настоящий клиент и поддельный в тестах).

### Готовность к масштабированию

Сделано сразу, потому что потом это дорого менять:

- `family_id` в схеме;
- всё состояние в Postgres: история диалога, защита от повторной обработки по `update_id`, блокировка сообщений одного пользователя через `pg_advisory_lock`;
- миграции — отдельной командой под блокировкой;
- ограничение параллельной обработки и лимит сообщений в час.

Включается по необходимости: webhook вместо polling (ядро бота `Process` не зависит от транспорта), очередь на Postgres, раздельный запуск API и обработчиков, авторизация панели (Telegram Mini App), разбор простых сообщений без LLM.

## Допущения

- Один запуск сервиса обслуживает одну семью; валюта — рубли; часовой пояс общий.
- Глава семьи в боте тоже видит только свои траты; все траты — в панели.
- «Последняя трата» — последняя добавленная, а не самая поздняя по дате.
- «За неделю» — последние 7 дней, «на этой неделе» — с понедельника, «в этом месяце» — с 1-го числа.
- Бот отвечает только в личных сообщениях: в групповом чате ответ увидели бы все.

## Ограничения и что дальше

- LLM подключается через OpenAI-совместимый API, чтобы провайдер менялся одной настройкой. У Claude этот режим [не рекомендован для продакшена](https://platform.claude.com/docs/en/api/openai-sdk) (нет кэширования промта, `strict` игнорируется); для продакшена стоит добавить нативный клиент Anthropic.
- Редактирование сообщения в Telegram не меняет трату.
- Контекст диалога — последние 10 сообщений за 6 часов.

## Тесты

make test   # docker compose run --rm test: go test -race на Postgres из compose

Интеграционные тесты идут на настоящем Postgres: изоляция пользователей, фильтры и суммы, защита от повторов, блокировка, API, агент с поддельной LLM (в том числе попытки тронуть чужую трату), бот (группы, `/start`, посторонние, лимиты).
