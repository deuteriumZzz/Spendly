# Spendly — учёт семейных расходов

Член семьи пишет боту в Telegram «кофе 350», и трата сохраняется: сумму, категорию и дату бот определяет сам. Глава семьи видит траты всех в веб-панели.

## Быстрый старт

```bash
make up
```

Это `cp .env.example .env && docker compose up --build`. Поднимутся Postgres, разовые миграции и приложение.

- Панель: http://localhost:8080 — сразу с демо-семьёй (`SEED_DEMO=true`).
- Документация API: http://localhost:8080/docs (OpenAPI: `/api/openapi.yaml`).

Чтобы заработал бот, в `.env` нужны два значения:

- `TELEGRAM_TOKEN` — токен от [@BotFather](https://t.me/BotFather);
- `LLM_API_KEY` — ключ провайдера LLM. По умолчанию Claude (`claude-opus-5-5`); OpenAI, OpenRouter и Ollama — примеры в `.env.example`.

Без токена приложение запускается без бота, панель работает.

## Как проверить за 5 минут

1. `make up` и открыть панель: быстрые периоды, фильтры по участнику и категории, поиск по комментарию, добавление, изменение, удаление. На телефоне строки складываются в компактный список.
2. Указать токен и ключ в `.env`, `make up`, написать боту:
   - `кофе 350`, `такси 1200 вчера`
   - `сколько потратил на еду в этом месяце`, `покажи траты за неделю`
   - `последнее было не 350, а 450`
   - `удали такси`
3. Траты из бота появятся в панели. Второй аккаунт Telegram увидит в боте только свои траты.
4. `make test` — тесты в контейнере, локальный Go не нужен.
5. `make eval` — 41 фраза против настоящей модели из `.env`, отчёт в `docs/eval-results.md`.

## Конфигурация

|---|---|---|
| `TELEGRAM_TOKEN` | — | токен бота; пусто — бот выключен |
| `LLM_BASE_URL` | `https://api.anthropic.com/v1/` | любой OpenAI-совместимый `/chat/completions` с tool calling |
| `LLM_API_KEY` | — | ключ провайдера (для Ollama не нужен) |
| `LLM_MODEL` | — | модель; обязательна, если задан токен бота |

| `SEED_DEMO` | `false` (`true` в `.env.example`) | демо-семья в пустой базе |

| `LOG_LEVEL` | `info` | `debug` — в логах видны вызовы инструментов агента |

## Архитектура

Один Go-бинарник, Postgres. Подкоманды: `serve` (API, панель, бот) и `migrate`.

```
Telegram ──long polling──► bot ──► agent ──► LLM (OpenAI-совместимый API)
                                     │ tools
                                     ▼
                         db.ForUser(user)      — только траты автора сообщения
                                     │
Браузер ──► api (REST) ──► db.ForFamily(family) — траты всей семьи
                                     │
                                  Postgres
```

| Пакет | Что делает |
|---|---|
| `internal/expense` | модель, деньги, категории, валидация, SQL; хранилище, ограниченное семьёй или пользователем |
| `internal/agent` | цикл tool calling, 5 инструментов, системный промт, LLM-клиент |
| `internal/bot` | приём сообщений: личка, `/start`, доступ, защита от повторов, лимиты, история |
| `internal/api` | REST API, OpenAPI, раздача панели |
| `web/index.html` | панель на чистом JS |
| `migrations/` | схема (goose) |

### Ключевые решения

- **Изоляция пользователей обеспечивается кодом, а не промтом.** Агент получает только хранилище `db.ForUser(...)`, созданное из `message.From.ID`. Ни один инструмент не принимает `user_id`, а владелец проверяется в каждом SQL-запросе (`WHERE ... AND user_id = $n`). Чужой id от модели даёт «не найдено» — это проверяют тесты.
- **Tool calling вместо «фраза → JSON».** Для «удали такси» и «последнее было не 350» модели нужно видеть траты пользователя: сначала `find_expenses`, потом `update_expense` / `delete_expense` по id. Если подходит несколько трат, бот спрашивает, а не угадывает.
- **Суммы считает SQL** (`sum_expenses`), модель только формулирует ответ.
- **Деньги — копейки в `int64`**, в БД `NUMERIC(12,2)`. `spent_at` — `DATE`, «сегодня» считается в `APP_TIMEZONE`.
- **Ответ модели проверяется так же, как запрос из API:** категория из списка (плюс `CHECK` в БД), сумма больше нуля, дата не в будущем. Ошибка возвращается модели, и она переспрашивает пользователя.
- **Без лишних слоёв.** Нет service/repository-интерфейсов с одной реализацией; интерфейс один — LLM (настоящий клиент и поддельный в тестах).

### Готовность к масштабированию

Сделано сразу, потому что потом это дорого менять:

- `family_id` в схеме;
- всё состояние в Postgres: история диалога, защита от повторной обработки по `update_id`, блокировка сообщений одного пользователя через `pg_advisory_lock`;
- миграции — отдельной командой под блокировкой;
- ограничение параллельной обработки и лимит сообщений в час.

Включается по необходимости: webhook вместо polling (ядро бота `Process` не зависит от транспорта), очередь на Postgres, раздельный запуск API и обработчиков, авторизация панели (Telegram Mini App), разбор простых сообщений без LLM.

## Качество агента

Логику агента покрывают обычные тесты с поддельной LLM. Насколько хорошо модель понимает людей, меряет `make eval`: 41 фраза в шести группах — запись, просмотр, изменение, удаление, безопасность, прочее.

- Случай засчитывается по итоговому состоянию БД и аргументам вызовов инструментов, а не по формулировке ответа. Например, «последнее было не 350, а 450» верно, только если у кофе стала сумма 450 ₽ и ни одна другая трата не изменилась.
- «Сегодня» в наборе зафиксировано (16.10.2026, пятница), поэтому даты проверяются точно: «за неделю» — с 10.10, «на этой неделе» — с 12.10.
- У каждого случая своя пара пользователей, случаи идут параллельно.
- Прогон тратит запросы к API: около 40 диалогов по 2–3 вызова модели.

Механизм eval проверен на заглушке LLM. Прогон на настоящей модели ещё не делался — при разработке не было ключа. Результаты появятся в `docs/eval-results.md` после `make eval`.

## Безопасность и приватность

**Бот.** Изоляция обеспечивается кодом, а не промтом (см. «Ключевые решения»). Бот отвечает только в личных сообщениях. Если задан `FAMILY_MEMBERS`, посторонний получает отказ и свой ID; открытый режим (пустой `FAMILY_MEMBERS`) нужен для проверки, при запуске в лог пишется предупреждение.

**Панель.** Авторизации нет по ТЗ, поэтому защищено то, что можно защитить без неё — чтобы чужой сайт, открытый в браузере главы семьи, не добрался до трат:

- по умолчанию панель слушает только `127.0.0.1`;
- **DNS rebinding:** запросы с доменным именем в `Host`, которого нет в `PANEL_HOSTS`, отклоняются (421). Иначе страница злоумышленника, чей домен указывает на 127.0.0.1, прочитала бы все траты. `localhost` и IP-адреса разрешены всегда;
- **CSRF:** стандартный `http.CrossOriginProtection` отклоняет изменяющие запросы с чужих сайтов (403), в том числе «простые» POST без CORS-проверки;
- запрет встраивания во фрейм и `nosniff`;
- скрипты Swagger UI с CDN закреплены SRI-хэшами: подменённый файл браузер не выполнит.

Открывать панель в интернет без прокси с авторизацией или VPN не стоит — это прямо следует из «без авторизации» в ТЗ.

**Что уходит провайдеру LLM:** текст сообщения, история диалога за 6 часов и траты этого пользователя, которые вернули инструменты. Траты других членов семьи и их имена не уходят. Если это неприемлемо — локальная модель через `LLM_BASE_URL`.

**Хранение.** Переписка с ботом удаляется через 7 дней (нужна для контекста, лимитов и защиты от повторов). Траты хранятся бессрочно. В логах уровня `info` нет текстов сообщений и сумм; токен бота библиотека маскирует в ошибках.

**Проверено:** `govulncheck` — уязвимостей в зависимостях нет; `gosec` включён в линтер и CI.

## Допущения

- Один запуск сервиса обслуживает одну семью; валюта — рубли; часовой пояс общий.
- Глава семьи в боте тоже видит только свои траты; все траты — в панели.
- «Последняя трата» — последняя добавленная, а не самая поздняя по дате.
- «За неделю» — последние 7 дней, «на этой неделе» — с понедельника, «в этом месяце» — с 1-го числа.
- Бот отвечает только в личных сообщениях: в групповом чате ответ увидели бы все.

## Ограничения и что дальше

- Качество агента на настоящей модели не измерено: нужен прогон `make eval` с ключом (см. «Качество агента»).
- Бот не проверялся вживую в Telegram — при разработке не было токена. Обработка сообщений покрыта тестами на уровне `bot.Process`.
- Локальная модель (Ollama) в compose не добавлена: небольшие модели заметно хуже справляются с вызовом инструментов, а скачивание весов на несколько гигабайт замедлит первый запуск. Подключается через `LLM_BASE_URL`.
- LLM подключается через OpenAI-совместимый API, чтобы провайдер менялся одной настройкой. У Claude этот режим [не рекомендован для продакшена](https://platform.claude.com/docs/en/api/openai-sdk) (нет кэширования промта, `strict` игнорируется); для продакшена стоит добавить нативный клиент Anthropic.
- Редактирование сообщения в Telegram не меняет трату.
- Контекст диалога — последние 10 сообщений за 6 часов.

### Нюансы поведения

- **Сбой модели после изменения данных.** Если трата уже записана, а следующий вызов LLM упал, бот перечисляет сделанное («Сделано: записано: кофе — 350 ₽…»), а не пишет «не получилось» — иначе пользователь повторит сообщение и получит дубль.
- **Очередь сообщений.** Сообщения одного пользователя обрабатываются по очереди; пачка сообщений от одного человека не занимает все слоты обработки и не задерживает остальных.
- **Остановка сервиса.** Сообщения, которые обрабатывались в момент остановки, остаются без ответа: long polling уже подтвердил их получение.
- **Смена бота на той же базе.** Номера `update_id` нового бота теоретически могут совпасть со старыми, и такое сообщение будет принято за повтор. Для новой базы не актуально.
- **Часовые пояса.** «Сегодня» в форме панели берётся из пояса браузера, проверка «не в будущем» — в `APP_TIMEZONE`. Около полуночи при разных поясах сервер может отклонить «сегодняшнюю» дату.
- **«1.200» в панели** не принимается: точка — десятичный разделитель. Бот такую запись понимает через модель.

## Тесты

```bash
make test   # docker compose run --rm test: go test -race на Postgres из compose
make lint   # golangci-lint
make eval   # агент против настоящей модели
```

Интеграционные тесты идут на настоящем Postgres: изоляция пользователей, фильтры и суммы, защита от повторов, блокировка, API, агент с поддельной LLM (в том числе попытки тронуть чужую трату), бот (группы, `/start`, посторонние, лимиты).

CI (`.github/workflows/ci.yml`): gofmt, vet, тесты с `-race` на Postgres, golangci-lint, сборка образа.
